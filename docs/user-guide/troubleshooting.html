Troubleshooting

This page lists every error you can hit when using fastapi-chameleon, what it means, and the fix. Errors raised by the package itself are FastAPIChameleonException or a subclass. Errors raised by Chameleon while compiling or rendering a template come through as ValueError, NameError, AttributeError, or one of Chameleon’s own exception types. All of them surface as a 500 to the browser and a traceback in the server log, so start from the log.

Errors from the package

FastAPIChameleonException: You must call global_init() before rendering templates.

A decorated view, response(), or engine.render() ran before global_init(). Call global_init(template_folder) once at startup, in the module that creates the app, before requests are served. In tests, use a fixture that calls it and clears the engine afterwards. See Testing and CI.

FastAPIChameleonException: The template_folder must be specified.

global_init() was called with an empty string or None. Pass the path to your templates folder.

FastAPIChameleonException: The specified template folder must be a folder, it's not: ...

The path does not exist or is a file. The message shows the path as the package saw it. Relative paths resolve against the current working directory, which differs between python main.py, uvicorn main:app, and your test runner. Build the path from __file__ instead:

BASE_DIR = Path(__file__).resolve().parent
fastapi_chameleon.global_init(BASE_DIR / 'templates')

FastAPIChameleonException: Invalid return type <class 'NoneType'>, we expected a dict or fastapi.Response as the return value.

The view returned something other than a dict or a fastapi.Response. NoneType almost always means a missing return. Other types mean you returned a model object, a list, or a string. Convert it: model.model_dump() for Pydantic, dataclasses.asdict(obj) for dataclasses, {'items': items} for a list.

500 Internal Server Error, log shows FastAPIChameleonNotFoundException: The URL resulted in a 404 response.

not_found() was called from code that is not below a @template-decorated view. The same applies to FastAPIChameleonGenericException: The URL resulted in an error. from generic_error(). Nothing caught the exception, so FastAPI returned a 500. Decorate the route, or raise fastapi.HTTPException(status_code=404) from undecorated code. See Friendly Error Pages.

TypeError: 'PosixPath' object is not iterable inside chameleon/loader.py

Versions up to 0.1.18 accepted a pathlib.Path in global_init() but Chameleon’s loader could not use it. Upgrade, or wrap the path in str(). Current versions accept any os.PathLike.

Errors from Chameleon

ValueError: Template not found: home/missing.pt.

The template path does not exist under the folder given to global_init(). The path in the message is relative to that folder. Check for a typo, a wrong subfolder, or .html versus .pt. If the view uses the bare @template form, the expected path is {module}/{function}.html or .pt, where module is the last segment of the view’s module name. A view named index in views/home.py wants home/index.pt. If the path looks right but the file is still not found, the engine may be pointing at the wrong folder because global_init() ran after the view module was imported. See Decorating Views.

NameError: items

The template referenced a variable the view did not return. Chameleon names the missing variable. Add it to the dict the view returns, or guard it in the template with tal:condition. The same error appears when a layout macro uses a variable that one of its pages does not provide.

AttributeError: 'NoneType' object has no attribute 'upper'

An expression inside ${ } or a tal: attribute failed. Chameleon appends the expression that failed, for example - Expression: "title.upper()". Fix the data the view returns or make the expression tolerate the value.

chameleon.exc.LanguageError or chameleon.exc.ExpressionError

The template itself has a bug: an invalid tal: attribute such as tal:repeat="x" without a sequence, or a Python expression with a syntax error. These are raised the first time the template is compiled, which is the first request that uses it. The message includes the offending string and the file name.

Behaviour that looks like a bug

Template edits are not showing up

Templates are compiled once and cached. Pass auto_reload=True to global_init() during development. If you already did, check whether global_init() is being called twice: the second call is ignored unless cache_init=False, so the first call’s settings win. See Configuration.

The wrong template renders, or the bare @template form cannot find a file that exists

Template name inference runs when the view module is imported and uses the folder configured at that moment. If global_init() had not run yet, the folder defaulted to templates relative to the current working directory and a later global_init() did not re-resolve the name. Move global_init() above the view imports, or name the template explicitly.

My 404 page returns JSON

The request never reached a decorated view. FastAPI’s router answered because no route matched. Add a catch-all route decorated with @template that calls not_found(), or register a FastAPI exception handler for 404 that returns fastapi_chameleon.response('errors/404.pt', status_code=404).

The error page itself fails with a 500

The error template is missing or broken. not_found() renders errors/404.pt by default, so create that file. A ValueError: Template not found: errors/404.pt. in the log confirms this cause.

Fix order

Work from the outside in: make sure global_init() runs once, first, with an absolute path. Then check the view returns a dict. Then check the template path. Then read Chameleon’s message for the variable or expression it names.
